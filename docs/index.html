One hard rule: if the backend call needs login/auth, always use Edge Worker. Nothing else can change that answer.

A few more things to think about (this won't change the answer above)

How fresh does the data need to be? If people must always see the newest value with no delay, use Edge Worker. If it's fine to update on a schedule or on publish, JSON-to-HTML is simpler. If the API goes down, JSON-to-HTML still shows the last good page automatically — Edge Worker needs extra code to handle that.
Who will make changes later? If a content editor should be able to update the page without a developer, use JSON-to-HTML. If every small change needs a developer to write code and deploy it, that's the ongoing cost of Edge Worker — and if your team hasn't set up edge deployment before, budget time for that too.
Who fixes it when it breaks? Edge Worker is application code — it needs its own monitoring, logging, and someone on call, plus a fast way to roll back a bad deploy. JSON-to-HTML rides on the normal EDS publish and CDN setup, so there's less to watch — but a content or data change still needs someone (or something) to trigger a rebuild.
