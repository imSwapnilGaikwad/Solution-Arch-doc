JSON-to-HTML vs Edge Worker

Answer each question to get a recommended approach for your page.

Global constraint: the content overlay stays singular across the project - whichever pages end up JSON-to-HTML or Edge Worker, they all read from one canonical content source.
Hard gate: if the backend call needs per-request authentication, the answer is always Edge Worker - no other question can override it.
Question 1

Is the page SSR (server-side rendered)?

If it's not SSR, this decision doesn't apply - it's a custom block.

Question 2

Single template, but multiple pages?

One template generating many instances (for example product ID or branch ID).

Question 3 - hard gate

Does the backend call require authentication management (token exchange, session validation, hiding a secret)?

If yes, this overrides everything below - a static build-time page can't securely hold live credentials.

Question 4

Does the page have a fixed block and component structure?

A fixed structure locks the decision to JSON-to-HTML regardless of later answers.

Question 5

Does the page need to be present / authorable in Universal Editor?

Identifier resolved at page level, in-context editing required.

Question 6

Where should the JSON-to-HTML template live?

Universal Editor only supports flat key-value mapping - no looping.
